# azure-terraform-lab

> A learning sandbox for provisioning and tearing down Azure resources with Terraform, end-to-end.

## What this is

A learning sandbox that provisions and tears down a minimal Azure resource set (resource group, VNet, subnet, NIC, Linux VM) end-to-end via Terraform. The goal is to demonstrate the full `init / plan / apply / destroy` lifecycle, version-pinned providers, parameterized config, and zero-cost discipline (resources are destroyed in the same session they're created). Started as a portfolio piece tied to the AZ-104 learning path. Current state: Phase 4 of the setup roadmap — variables/outputs/README in place.

## How to run

```bash
# First-time setup
az login                                       # authenticate to Azure
terraform init                                 # download providers, write lockfile

# Loop (always plan-out → apply, never blind apply)
terraform plan -out=tfplan
terraform apply tfplan

# Inspect
terraform output                               # surface useful values
terraform output -raw vm_admin_password        # sensitive value, opt-in reveal

# Always end with
terraform plan -destroy -out=tfplan.destroy
terraform apply tfplan.destroy
```

Don't leave the VM running. Pair every `apply` with a `destroy` in the same session.

## Conventions

### Working style
- **Structure over prose.** Headers, bullets, short lines. Front-load the important.
- **One next step at a time.** Don't hand a 10-step plan and self-sequence — confirm each chunk.
- **Restate context** when referencing decisions from earlier in the session.

### Code style
- Follow existing patterns in this repo before introducing new ones.
- No comments unless the WHY is non-obvious. Identifiers should explain WHAT.
- Don't add error handling, fallbacks, or validation for cases that can't happen.
- Trust internal code and framework guarantees. Validate at system boundaries only.

### Testing
- This repo has no test suite. The integration test IS `terraform plan` (compares desired state to actual cloud state) and a successful `apply` + `destroy` round trip.
- Always run `terraform fmt` and `terraform validate` before committing.

## SDLC discipline (sdlc-core)

This repo uses the `sdlc-core` plugin for lifecycle gating:

- **Secret scan + file protection** — block writes containing credentials or to sensitive paths.
- **Type-check on edit** — advisory; surfaces errors, doesn't block.
- **Review-freshness gate** — `git push` is blocked until `/review` has run on the current HEAD. Run `/review` to update `.last-review`.
- **Ship** — use `/ship` to stage, commit, push, and open a PR.

To loosen or tighten any gate per-repo, edit `.claude/settings.json` → `enabledPlugins` (set the plugin entry to `false` to disable everything from it).

## Project-specific notes

- **Authentication is via `az login`**, not a service principal. The azurerm provider inherits the active subscription from the CLI. Pin via `ARM_SUBSCRIPTION_ID` env var if you ever have multiple subscriptions.
- **Free-trial quota traps:** the original B-series (`B1s`, `B2s`) is capacity-restricted; v2 B-series (`Basv2`, `Bsv2`, `Bpsv2`) has 0 default quota on trial accounts. This repo uses `Standard_D2s_v6` (Dsv6 family — 10 vCPU trial quota in centralus). To swap, check `az vm list-usage --location <region>` first.
- **VM has no public IP and no NSG.** Lab is designed for destroy-same-session. Don't add a public IP without also adding an NSG.
- **State file holds the VM admin password** generated by `random_password`. State is gitignored. If you ever migrate to remote state (Phase 5), encrypt the backend.
- **Image version is pinned** (`24.04.202606060`). Find current options with `az vm image list --publisher Canonical --offer ubuntu-24_04-lts --sku server --all`.
